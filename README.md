## 🛠 Стек технологий и библиотеки

### **Frontend (`apps/web`)**

- **Фреймворк:** [Next.js 15+](https://nextjs.org/) (App Router, Server & Client Components)
- **Язык:** TypeScript
- **Стилизация:** Tailwind CSS + CSS Variables (поддержка Dark/Light тем без скачков гидратации)
- **Иконки:** `lucide-react`
- **Состояние (State Management):** React Context API (`CartContext`) с персистентностью в `localStorage`
- **Анимации и UI:** Кастомные модальные окна, выдвижная корзина (Drawer), адаптивные сетки

### **Backend (`apps/api`)**

- **Фреймворк:** [NestJS 11](https://nestjs.com/)
- **Язык:** TypeScript
- **База данных:** SQLite
- **ORM / Query Builder:** TypeORM
- **Безопасность и Auth:** `@nestjs/jwt`, `bcrypt` / `passport-jwt`
- **Валидация:** `class-validator`, `class-transformer`

## 🏗 Архитектура и паттерны проектирования

Проект организован по типу **Modular Monorepo (Модульный монорепозиторий)** с использованием **npm workspaces**:

```text
kvarta-coffee/
├── apps/
│   ├── api/                  # NestJS Backend (REST API)
│   │   ├── src/
│   │   │   ├── auth/         # Модуль аутентификации (JWT)
│   │   │   ├── products/     # Модуль каталога спешелти-лотов
│   │   │   └── leads/        # Модуль обработки заказов и заявок
│   │   └── database.sqlite
│   └── web/                  # Next.js Frontend (App Router)
│       ├── app/              # Маршрутизация (Catalog, Account, layout)
│       └── src/
│           ├── components/   # UI-компоненты (Header, Cart, Modal, Sections)
│           └── context/      # Глобальный контекст корзины
└── package.json              # Корневой конфиг монорепозитория
```

### **Использованные паттерны проектирования:**

1. **Module Pattern (NestJS):** Четкое разделение ответственности на независимые модули (`AuthModule`, `ProductsModule`, `LeadsModule`).
2. **DTO & Validation Pipe Pattern:** Строгая валидация входящих HTTP-запросов с помощью Data Transfer Objects (`CreateProductDto`, `CreateLeadDto`).
3. **Repository Pattern (TypeORM):** Абстракция работы с базой данных для лёгкой замены СУБД (например, с SQLite на PostgreSQL в production).
4. **Provider / Context Pattern (React):** Единый источник правды для управления состоянием корзины покупок (`CartContext`).
5. **Component-Driven Architecture:** Модульные UI-компоненты с разграничением ответственности (Server Components для SEO/рендеринга и Client Components для интерактивности).

## 🚀 Что было реализовано

### **Интерфейс и Продуктовый функционал (Frontend):**

- **Главный лендинг и Каталог:** Презентация обжарочной мастерской, история, интерактивный фильтр по профилям обжарки (Эспрессо, Фильтр, Под молоко).
- **Управление корзиной:** Добавление/удаление товаров, автоматический подсчет стоимости, синхронизация с `localStorage`, динамический счетчик товаров в шапке.
- **Быстрое оформление заказа (Checkout):** Выдвижная корзина (Cart Drawer) с интеграцией отправки лида/заказа на NestJS backend (`POST /leads`).
- **Модальное окно заявки:** Быстрый звонок / консультация по подбору зерна.
- **Кастомный переключатель тем:** Темный и светлый режим в фирменной кофейной палитре (Dark/Light mode).
- **Личный кабинет & Панель администратора (`/account`):**
  - Авторизация и регистрация пользователей.
  - Панель администратора для добавления новых спешелти-лотов в каталог через API (`POST /products`).
  - Стилизованные элементы управления (кастомный выбор профилей обжарки, скрытие системных стрелок в полях ввода цен).

### **Серверный функционал и API (Backend):**

- **Авторизация (JWT):** Хеширование паролей, выдача Access Tokens.
- **CRUD Каталога:** Получение списка спешелти-сортов, добавление новых лотов.
- **Заказы и Лиды:** Прием обратных заявок и оформленных корзин с клиента.
- **CORS & Middleware:** Настроенная безопасность для взаимодействия между портами `:3000` и `:4000`.

## 🔑 Управление ключами и переменными окружения (ENV)

Все адреса подключения к API вынесены в переменные окружения для безопасного деплоя:

- В директории `apps/web/` создается файл `.env.local`:
  ```env
  NEXT_PUBLIC_API_URL=http://localhost:4000
  ```
  _(При деплое на Vercel значение `NEXT_PUBLIC_API_URL` меняется на URL выкаченного бэкенда)._

## 💻 Инструкция по локальному запуску

### **1. Клонирование репозитория и установка зависимостей**

```bash
git clone https://github.com/your-username/kvarta-coffee.git
cd kvarta-coffee
npm install
```

### **2. Запуск Backend (NestJS)**

В отдельном терминале:

```bash
cd apps/api
npm run start:dev
```

_Сервер запустится по адресу: `http://localhost:4000`_

### **3. Запуск Frontend (Next.js)**

Во втором терминале:

```bash
cd apps/web
npm run dev
```

_Приложение откроется по адресу: `http://localhost:3000`_

## 🧠 Возникшие сложности и решения

1. **Несовместимость ESM и CommonJS в монорепозитории:** При запуске NestJS возникали конфликты с загрузкой модулей SQLite и TypeORM. Решено явной настройкой конфигурации скриптов и окружения в `apps/api/package.json`.
2. **Кэширование Next.js App Router при горячей перезагрузке:** При внесении изменений в UI клиентский компонент закэшировал старую версию сборки. Проблема решена очисткой `.next` артефактов (`rm -rf apps/web/.next`).
3. **Гидратация при переключении тем:** Для предотвращения "мигания" интерфейса при загрузке темы из `localStorage` были применены валидные начальные состояния в React-компонентах.
